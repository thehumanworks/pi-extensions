# Independent write-controls review v1.0.0

**Verdict: one documentation/test blocker; write-dispatch controls otherwise pass the requested offline review.** No live endpoint or mutation was used.

## Blocker

- **Session-replacement scope is documented and tested incorrectly.** Pi 1.0.4 defines `session_shutdown` as firing before the extension runtime is torn down for `new`, `resume`, or `fork` (`node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:616-621`). The extension stores the TUI override only in factory-local `allowWrites` (`index.ts:47-57`), so that override is recreated from environment/CLI state when a replacement runtime is constructed. This contradicts README's claim that the override survives “session replacement” (`README.md:107-109`). The fake test emits shutdown/start on one already-constructed fake extension and expects the override to persist (`tests/extension.test.ts:254-257`); it does not model Pi's runtime teardown/recreation. **Reproduction:** in TUI, toggle ON with env unset and no CLI flag, then start/resume/fork a session; the next runtime initializes OFF, not ON. Update the scope claim and test replacement by constructing a fresh runtime. Tree navigation is different: `session_tree` resets/closes the service but does not itself replace the extension runtime (`index.ts:69-73`), so its in-memory toggle persists while handles/cursors/plans do not.

## Verified controls and write safety

- The boolean `--atlassian-allow-writes` is registered with no default (`index.ts:52-57`). Pi 1.0.4 types support boolean flags and `getFlag` (`node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:1202-1213`); Pi applies parsed extension flag values after extension loading (`node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session-services.js:8-29,112`). Therefore reading lazily/session-start is correct. Bare CLI true overrides env; omission inherits `ATLASSIAN_ALLOW_WRITES === '1'`; no false/negative CLI switch is registered. Mock precedence cases pass (`tests/extension.test.ts:225-243`).
- `/atlassian-writes` is a no-argument TUI-only toggle guarded by both `ctx.mode === 'tui'` and `ctx.hasUI`; invalid args and non-TUI calls do not toggle (`index.ts:74-90`). It is not a model tool. Status/footer is derived from the effective state (`index.ts:55-60,87-90`); mutation tools remain codemode-exposed, with only discovery direct (`index.ts:93-99`).
- Controls do not mutate env/files or invoke network: the command only updates runtime-local state and an already-created service (`index.ts:87-90`; `src/service.ts:404-409`). Status reports `networkChecked:false` (`src/service.ts:288-292`). Mock tests check env preservation, zero fetches, no model-callable setter and injected-config isolation (`tests/extension.test.ts:238-264`; `tests/write-controls-cases.ts:45-56`). Toggling preserves existing source/cursor handles; mock test recovers exact CRLF/Unicode source and continues the cursor without another fetch (`tests/extension.test.ts:270-297`); service control test confirms the same (`tests/write-controls-cases.ts:21-39`).
- Default read-only; planning is local and snapshots the exact request/payload into a preview with digest and a single-use plan. Apply requires exact planId confirmation, enabled runtime opt-in and an approval callback returning exactly `true`; adapter requires UI and presents the full preview (`src/service.ts:344-361,363-388`; `index.ts:100-106`). It consumes the plan before awaiting approval; denied/concurrent/cancelled uses cannot replay. Mutations are never retried (`src/transport.ts:72-86`). Confluence update plans require expected version and re-read before mutation; Jira explicitly has no general atomic CAS (`src/service.ts:346-350,379-387`; `README.md:121`).
- OFF increments generation, clears plans, and aborts pending applies; generation checks after approval/version read plus transport abort-aware concurrency queue prevent an undispatched mutation. OFF→ON cannot revive those plans. Mock reproductions cover pending approval, abort-ignoring version fetch, and queued mutation while retaining unrelated in-flight read (`src/service.ts:64-73,370-388`; `src/transport.ts:55-63`; `tests/write-controls-cases.ts:59-118`). Neither docs nor UI claim OFF rolls back a dispatched mutation (`index.ts:90`; `README.md:111`). Closed service cannot be revived (`src/service.ts:404-409`).
