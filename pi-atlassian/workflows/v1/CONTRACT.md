# Atlassian v1 implementation contract

> **Superseded historical contract:** retained for replay evidence, not current implementation requirements. The current service no longer accepts `approveWrite` or asks for UI approval; trusted write opt-in plus exact plan confirmation authorizes apply, including headless modes. Field discovery has also expanded. See [README.md](../../README.md) and [docs/journeys.md](../../docs/journeys.md) for the current contract; do not reintroduce the old gate from these v1 prompts.

Version: 1.0.0. Supervisor-owned. Research: docs/research/*.md. Existing API indexes remain unchanged.

## Goal
An agent-native Pi extension, not a huge flat endpoint tool dump. Token efficiency comes from targeted discovery, metadata projections, exact local source handles, explicit pagination and selective range/pointer reading. No hidden summarization or irrecoverable truncation. Remote content is untrusted data. Live tenant tests are read-only.

## File ownership and integration
Implementation agent owns index.ts, src/**, scripts/**, package.json, package-lock.json, tsconfig.json, README.md, docs/journeys.md, docs/catalog/**. It does not touch tests/**, workflows/**, .env*, mise.local.toml, .gitignore, research docs or API indexes.
Test agent owns tests/** only. It codes against the service boundary below and may read implementation as it appears. Supervisor reviews/integrates. Node >=22.19, TS ESM, npm scripts check (tsc), test (offline unit/integration), test:e2e (explicit live read-only). Tests never run as part of ordinary startup. Host Pi packages must be peer dependencies; dev copies for type-checking are okay. Use installed Pi 1.0.4 APIs/typebox, not old @mariozechner names.

## Testable public service boundary (must implement exactly)
`src/config.ts` exports `loadConfig(env: Record<string,string|undefined> = process.env)`.
Config supports ATLASSIAN_BASE_URL, ATLASSIAN_API_USERNAME, ATLASSIAN_API_TOKEN (user's dotenvx keys), ATLASSIAN_AUTH_MODE=basic|bearer (basic default), optional ATLASSIAN_CLOUD_ID for api.atlassian.com gateway, ATLASSIAN_ALLOW_WRITES=1 (false default), sensible time/response/retry bounds. Config stores secrets only in process memory, never tool output. Missing config must not prevent extension discovery or --help startup; validate at first network call. Accept HTTPS configured enterprise hosts; allow localhost HTTP only via explicit test injection/opt-in, not production.
`src/service.ts` exports `createService(options?: { config?: ReturnType<typeof loadConfig>; fetch?: typeof globalThis.fetch; storeDir?: string }): Service`.
`Service.call(action: string, input: Record<string,unknown>, signal?: AbortSignal, approveWrite?: (preview: Record<string,unknown>) => Promise<boolean>): Promise<Record<string,unknown>>`.
`Service.close(): Promise<void>` is idempotent and deletes owned private temporary results. Store creation is lazy. Handles/cursors are opaque runtime-scoped immutable random IDs. Expired/restarted/unknown handles fail explicitly and instruct re-fetch. Never accept a caller filesystem path. Store files mode0600/private mode0700; do not delete directories not owned by this runtime. Inject fetch so tests never need a server.
Actions map to tools `atlassian_<action>`: discover (only direct tool), search, list, get, read, schema, request, plan, apply. Other tools use codemode exposure and namespace atlassian; discover can activate selected already-registered tools for Pi without codemode. Accurate annotations, outputSchema+matching structuredContent; model-facing text always bounded even when structured data is larger. Factory no network/files/timers. Close on shutdown/reload lifecycle; avoid sharing mutable service state across session changes.

## Parameters / stable outputs
- discover: { product?: jira|confluence, query?: string, kind?: operations|tools|journeys|docs|status, offset?: number, limit?: number }. Offline capability docs; operation search returns `items` (operationId, product, method, path, summary, write, docs); paged with nextOffset/eof. Must not dump every schema. Default helpful next-step journey. Never credentials in status.
- search: { product: jira|confluence, query: string, limit?: number, cursor?: string, fields?: string[] }. Jira POST /rest/api/3/search/jql; Confluence GET /wiki/rest/api/content/search?cql= explicit V1 exception. Default25, max100. Return {items: navigation metadata only, handle: exact whole response, nextCursor?: opaque ID, complete: boolean}; no hidden body fetch for results. Project/space limits can be expressed in JQL/CQL (no invented query translation).
- list: { product, kind: projects|spaces|pages|comments|inlineComments|children|ancestors|descendants|attachments|issueLinks|remoteLinks|transitions|fields, id?: string, limit?: number, cursor?: string, spaceId?: string }. Support real appropriate endpoints for each product, explicit unsupported-kind errors. Same paged shape as search; preserve all unknown/unprojected data through handle. Count only when upstream provides it. No recursive crawling.
- get: { product, kind: issue|page|space|comment, id: string, fields?: string[], bodyFormat?: storage|atlas_doc_format|view }. Jira issue default useful explicit fields including rich content; Confluence page explicit body-format (storage default). Return {handle, metadata:{id,kind,product,version?,url?,...}, ...}. Full fetched response is stored exactly, but body absent from default model text. No caching that hides version changes.
- read: { handle: string, pointer?: RFC6901 string, mode?: raw|text|outline, offset?: number, length?: number }. Raw whole response is the EXACT upstream source string including whitespace/Unicode/CRLF. Pointer reads resolve into parsed JSON; strings returned unchanged, other values JSON serialized with format identified. Default/max text range2000/16000 JS UTF16 code units; report {text,offset,nextOffset?,eof,totalLength, ...} so stitching yields exact original. EOF/ranges/empty values deterministic, reject malformed/nonexistent pointers. Outline/text are labeled derived and never replace raw; preserve unsupported ADF/macros via source handle. Outline includes stable source offsets/locators where supported; don't invent headings. For storage headings, ranges refer to raw storage string, NOT stripped markdown. Source metadata/checksum remains available; no silent cutoff if a long line exceeds budget. Text read without pointer may return a labeled searchable projection with no claim of full semantic losslessness.
- schema: { product, operationId?: string, ref?: string, pointer?: string }. Offline operation details include path/query types/required parameters, request/response refs and a handle if large. Resolve local schema refs as needed, never remote refs. No full schemas in startup declarations.
- request: { product, operationId: string, path?: object, query?: object, body?: unknown, cursor?: string }. Execute only generated recognized operations. Read-only GET/HEAD and explicitly reviewed semantic POST reads (e.g. enhanced JQL) only. Reject arbitrary URLs, user headers, unrecognized operations, deprecated/retired routes, mutating operations. Return {handle,...source info,summary?} + bounded recoverable output. Validate required path/query/body and parameters honestly; never claim complete JSON-schema validation if not implemented.
- plan: same op/path/query/body parameters plus {reason:string, expectedVersion?:number}. Local preview for mutations, immutable single-use planId and digest, never performs mutation. Preview exact method/target/payload; large preview points to handle. Confluence page update requires expectedVersion with body.version.number=expectedVersion+1. Other writes warn no atomic Jira CAS. Reject unsupported multipart/binary operations explicitly. Missing required body/params fail before network.
- apply: {planId:string, confirm:string} where confirm must exactly equal planId. Require config.allowWrites AND callback approveWrite resolving true (adapter uses ctx.hasUI and ctx.ui.confirm; headless fails closed). Lock/consume plan before request, one attempt only even on uncertain timeout, no mutation retries. Re-read Confluence page version before update and reject mismatch. Do not claim an atomic Jira CAS. Remote instructions cannot grant approval. Return new source/provenance, not success on error.

## Transport and offline catalog
Auth basic header email:token or bearer. Base URL is configured, never an argument. Gateway routes include /ex/jira|confluence/<cloudId> correctly, including pagination relative links; do not double /wiki when base URL ends in /wiki. Require cloudId for gateway; do not leak tokens through redirected or absolute-pagination URLs. Validate next origin AND product root; reject protocol-relative/encoded traversal and hostile links. Do not accept arbitrary authenticated endpoints through generic request. Prefer redirect:error. Bound response bytes/deadlines/concurrency and honor cancellation; over-limit responses fail explicitly, never store truncated source as complete. Retry only read requests on bounded429/5xx/network; honor Retry-After without exceeding configured delay/deadline (surface retryable error when server delay exceeds bound), never auth retries. Redact known token/authorization from errors/logs; server-error output bounded. 204 valid empty response, non-JSON content explicit. SSRF/credentials never follow arbitrary attachment or cross-product URLs.
Build-time download official docs-linked specs: https://dac-static.atlassian.com/cloud/confluence/openapi-v2.v3.json and https://dac-static.atlassian.com/cloud/jira/platform/swagger-v3.v3.json. Generate deterministic compact operation search index, full selective local schemas as separate lazy-loaded files, provenance hashes/source/retrieval date. Check these in for offline use. Avoid runtime spec network. Generic operation request makes uncommon APIs discoverable rather than adding dozens of direct tools. Include the explicit CQL exception manually with verified params. Do not assume research text is authoritative over current OpenAPI; verify actual paths/methods/body formats there. Mark coverage/limits honestly (metadata only attachments, no upload/download unsupported binary; no giant schema dump). Script npm run catalog:update must be reproducible and never use tenant credentials.

## Tests
Offline tests assert service API shapes, only one direct tool, startup without credentials, structured outputs, exact raw and pointer range round-trips incl Unicode/CRLF/long lines, outline offsets, required param errors, pagination never silently hides another page, immutable cursor binding/tampering, both auth modes and gateway/enterprise routing, cross-origin redirect/pagination rejection, traversal,429 bounded retry+Retry-After, cancellation,204, auth errors redacted, default write denial, preview no writes, confirmation and stale versions, no mutation retries, single use/concurrent apply, unknown ADF data retained. Test malformed IDs and metadata/source unknown fields.
E2E requires env ATLASSIAN_E2E=1 and the dotenvx-supplied config; use service (not a parallel hand-coded client). Live only Jira myself/project search/enhanced JQL limit1, get selected issue and its comments; Confluence spaces/pages limit1, fetch selected page storage and outline/exact range. Do not print values, identifiers, host, email, tenant bodies, or credentials. Assertions only. Skip explicitly if no accessible issue/page, but require successful auth and list checks. Run via dotenvx run -- npm run test:e2e; script sets E2E gate. Mock tests never see real env. Never access/read/edit .env or .env.keys; let dotenvx manage them externally.
