## Capture and scheduler

**Capture is unblocked.** The salience regex at `src/capture.ts:72` now matches "Correction", and the clause-scoped temporal check at `src/capture.ts:78-98` isolates the "temporary" remark from the batch-size clause. I traced the exact ingestion correction through the overlap scorer: the batch-size clause scores far above the others, so only it is examined and the candidate stays long-lived. The new test at `test/capture.test.ts:230` exercises the frozen text both with and without an excerpt. The supersede path through the curator is unchanged and permits user-over-user, long-over-long replacement.

**Residual risk, verify on the first real ingestion.** An excerpt mismatch throws at `src/capture.ts:85`, which rejects the entire reflection batch, not just the offending candidate. The match is case-sensitive and only whitespace-normalized, so a model that capitalizes a mid-sentence quote or drops a comma fails every candidate in that batch. The pending state then retries the same transcript at the next session start, and a model that repeats the quoting style loops on paid calls with nothing saved. Recommend lowercasing and stripping terminal punctuation in the normalizer, and dropping only the bad candidate with a trace record rather than throwing. A second gap: a true but unrelated excerpt such as "This is durable" quoted for a temporary fact launders it into a long-lived memory, because clause expansion ignores overlap with the candidate body. Require the quoted clause to share at least one content token with the body or fall back to the whole-entry scan. Third, without an excerpt, a temporal qualifier in an adjacent sentence is now invisible to the expiry scanner. No test covers that case.

**Scheduler.** Cancellation on prompt, compaction, tree switch, and shutdown is wired in `index.ts:134-170`, backoff is written before inference at `src/scheduler.ts:47`, print and JSON modes are excluded by the mode check at `index.ts:113`, and the first-session overdue bug is fixed by seeding the schedule timestamp at `index.ts:83`. Shutdown and compaction no longer wait on a dream call. One concrete race remains. The timer guard at `src/scheduler.ts:37` is checked before an awaited file read, and the timer callback does not check for an already running task, so two overlapping calls to schedule can start two runs. The second run returns "already running" quickly and its cleanup at `src/scheduler.ts:51` clears the shared controller and promise, after which cancel cannot abort or await the first run. Fix by holding a placeholder before the await and checking the running promise in the callback. Separately, forced capture on compaction is still on the compaction path and can take two model calls. That is pre-existing and documented, not a dream issue.

## Dream oracle audit

Both expected values come from the helper at `test/dream-live.mjs:33`, which sets the preflight field to true whenever a command is known and to null otherwise. That rule never consulted the sources, so the defect is in the fixture generator, not in the two cases. Any future case built with that helper inherits it. The field should be an explicit per-case value derived from the quoted source, and the rescoring should be recorded as a fixture change with a new fixture hash alongside the frozen original.

- **Beacon staging, true to null: warranted.** The Beacon source at `test/dream-live.mjs:20` states one precondition, passed staging migrations, and never mentions a preflight. The prompt instructs null for unknown values. Under the evidence the preflight requirement is unknown, so null is correct and the original true was an artifact. Note that null, not false, is the right target because the evidence does not deny a preflight either.
- **Zephyr local, null to true: warranted, with a stated caveat.** The Zephyr source at `test/dream-live.mjs:21` says all Zephyr deployments require a passing preflight before any apply operation, and the case describes a Zephyr deployment. The general rule covers it even though command and limits are unknown. The caveat is that the rule is scoped to apply operations and the case does not say one occurs. I would accept true and record the ambiguity rather than treat it as settled. The abstention check is unaffected because the overgeneralization metric keys on the command field only.

**Effect on the numbers.** With both corrections, Beacon staging and Zephyr local pass in all four arms. Rescored action success becomes seven of eight for sources, compressed, and semantic, and eight of eight for combined. The remaining three failures are informative in different ways. The combined arm's single advantage is the Mercator payroll case, where the sources arm selected only two of the three Mercator items because the third did not fit the budget, so workers came back null. That is a budget packing effect, not generalization, and it rests on the one fixture where a long identical sentence repeats across sources. The compressed and semantic arms both fail the expired Mercator case because their only Mercator representation inherited the short expiry and vanished, taking the durable standard limits with it. That confirms the design hazard in candidate-only representations and is the strongest argument for keeping sources active, which production does. Co-injection is real: the combined Beacon run selected the condensed parent plus one of its own sources. With one sample per cell, none of these one-case differences support a direction claim.

The polluted-store ablation is the only planned model-in-the-loop evidence about size ceilings, so the ceiling question stays open until it runs.
